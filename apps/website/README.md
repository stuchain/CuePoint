# CuePoint website

The Astro site for CuePoint (Phase 17). Static output, built with Node 22.12 or newer.

## Commands

Run these in `apps/website`:

```
npm install      # or `npm ci` for a clean install from the lockfile
npm run dev      # dev server with hot reload
npm run build    # static site into dist/
npm run preview  # serve dist/ locally
npm run check    # astro check and tsc --noEmit
npm test         # vitest
npm run sync-tokens  # regenerate src/styles/tokens.generated.css from the app (build and dev do this first)
npm run og-image     # remake the placeholder social card
```

## The address and the `/CuePoint/` base

`site.config.ts` holds one address setting, `SITE_URL`. `astro.config.ts` derives Astro's `site` and
`base` from it. On GitHub Pages the base is `/CuePoint/`, so every link and asset must be built from
`import.meta.env.BASE_URL`; a bare `/guide/` breaks on Pages. A custom domain gives a base of `/`.
Local dev and preview also serve under `/CuePoint/`.

## The PUBLIC flag

`PUBLIC` in `site.config.ts` is `false`, so every page carries `noindex, nofollow`. It is switched on
in SITE-13, at launch.

## Product context

`PRODUCT.md` is the product and voice context the design skills read.

## Checks on the built site (SITE-03)

After `npm run build`, run these in `apps/website`. CI runs each as its own step in `website.yml`.

```
npm run check:site        # DEC-141's static rules on dist/: scripts/check-site.mjs
npm run test:e2e          # Playwright + axe at 375, 768, 1440 px; no sideways scroll; tap targets
npm run check:lighthouse  # Lighthouse CI: LCP, TBT, CLS, four category scores, script budget
```

- `check:site` prints `rule  page  message` per problem and exits 1. The rules are listed at the top of
  `scripts/check-site.mjs`; its JSON-LD requirements table cites Google's structured data docs.
  In a preview build (`PUBLIC` false) every page carries `noindex` on purpose, so the noindex-versus-sitemap
  rules are skipped, every page must carry `noindex`, and every indexable page must still be in the sitemap.
- `test:e2e` serves `dist/` with `astro preview` and opens every built page. Locally, point it at a
  Chromium: `PW_CHROMIUM_PATH=/opt/pw-browsers/chromium npm run test:e2e`. In CI,
  `npx playwright install --with-deps chromium` provides the browser.
- `check:lighthouse` needs Chrome: locally `CHROME_PATH=/opt/pw-browsers/chromium npm run check:lighthouse`.
  `lighthouserc.json` skips Lighthouse's `is-crawlable` audit while the site is a preview build (every page
  has `noindex`, which that audit fails); SITE-13 removes the skip when `PUBLIC` becomes true. The audit
  is skipped, not asserted off, because a failed audit also lowers the SEO category score.
  `resource-summary:script:size` (51200 bytes) is a cap on the total script weight of the page, not
  the 50 KB limit on JavaScript before the 3D loads. SITE-05 must add a separate measurement for that
  ("JS before the 3D loads <= 50 KB"), taken before the 3D chunk is requested; do not read this total
  as proof of it.
  When SITE-06/07/09/10 add the download page, a guide page and a blog post, add their URLs to
  `collect.url` in `lighthouserc.json`.
- `npm run sync-assets` also writes the favicon set into `public/` (copied from the app's icon files; those five files are git-ignored and regenerated by `build`, `check` and `test`). `check:site`, `test:e2e` and `check:lighthouse` need a built `dist/`.
- `website-links.yml` runs lychee over the external links of the built site every Monday and on demand,
  and opens an issue when one is dead.
